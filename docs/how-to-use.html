0 Какво ти трябва предварително

  • GitHub акаунт
  • Supabase акаунт (free = макс. 2 активни проекта; ако са заети — нов акаунт с друг имейл)
  • Vercel акаунт, вързан с GitHub
  • Node.js 20+
  • Лого (PNG), hero снимка, og изображение

1 Създай repo от темплейта

  1. Отвори github.com/quantomR/storefront-template
  2. Зелен бутон Use this template → Create a new repository
  3. Име = името на новия сайт → Create repository
  4. Клонирай:
git clone https://github.com/<акаунт>/<repo>.git
cd <repo>
⚠️ Vercel „Blocked" deploy: commit author-ът трябва да е GitHub акаунтът, вързан с Vercel: 
git config user.name "<github-username>"
git config user.email "<id>+<username>@users.noreply.github.com"
ID-то се вижда на api.github.com/users/<username>

2 Инсталация

npm install

.npmrc в repo-то решава peer конфликтите — не го трий.

3 Брандиране — src/config/brand.js

Единственият код файл, който пипаш.

💡 Проверка: npm run dev — сайтът трябва да е в новите цветове без да пипаш нищо друго.

4 Асети (фиксирани имена — презапиши файловете)

  • public/logo.png — лого (header + login)
  • public/favicon.png — иконка за таба
  • public/og.jpg — при споделяне (1200×630)
  • src/assets/hero.jpg — снимката на началната страница
💡 Малка/размазана снимка → AI upscale (Real-ESRGAN) преди да я сложиш.

5 Текстове

  1. src/i18n/bg.json + en.json — пренапиши маркетинговите текстове
  2. privacy.text — задължително замени placeholder политиката (checkout изисква съгласие с нея)
  3. Името на бранда НЕ се пише в json — ползвай {{brand}}
npm run check:i18n

6 Supabase

  1. New project на supabase.com (запиши database паролата)
  2. SQL Editor → копирай целия supabase/schema.sql → Run
  3. При notice за storage политики: Storage → product-images → Policies → добави ръчно: select (всички), insert/update/delete (authenticated)
  4. Демо продуктите от seed-а — изтрий ги после през админа
  5. Authentication → Users → Add user:
    • Email: admin@<domain от brand.js>
    • Парола: избери; ✅ Auto Confirm User
    • Входът в сайта после е само с частта преди @ (напр. admin)

7 Env променливи

cp .env.example .env.local

Попълни от Supabase → Project Settings → API:

VITE_SUPABASE_URL=https://xxxx.supabase.co
VITE_SUPABASE_ANON_KEY=<anon / publishable key>

8 Локална проверка

npm run dev
  • Публичният сайт е брандиран
  • /<adminSlug> → login → влизане успешно
  • Категория + продукт (цветове/размери според нуждите) + снимки
  • Продуктът се вижда в магазина; тестова поръчка минава
  • npm run check && npm run build — чисти

9 Email известия (по избор — може и по-късно)

npx supabase functions deploy send-email --project-ref <ref>
npx supabase secrets set GMAIL_USER=you@gmail.com GMAIL_APP_PASSWORD=xxxx SITE_NAME="Име" --project-ref <ref>

GMAIL_APP_PASSWORD = Google App Password (изисква 2FA на Gmail). После: админ → Настройки → „Имейл за известия".

10 Vercel

  1. Пушни промените: git add -A && git commit -m "brand setup" && git push
  2. vercel.com → Add New → Project → импортирай repo-то (Framework: Vite)
  3. Environment Variables: VITE_SUPABASE_URL + VITE_SUPABASE_ANON_KEY
  4. Deploy

11 Финален чеклист

  • Responsive: телефон (375), таблет (768), десктоп (1280)
  • Админ слъгът НЕ е линкнат в публичния сайт
  • Демо продуктите са заменени с реални
  • privacy.text е реална политика
  • siteUrl попълнен + нов deploy (SEO)
  • Сподели линк в чат — preview-то показва og.jpg
  • npm run check чист
